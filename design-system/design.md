# 카드뉴스 디자인 규칙 (design.md)

> **이 문서는 무엇인가요?**
> 인스타그램 카드뉴스를 만들 때 "어떻게 생겨야 하는지"를 정해 놓은 **규칙집**입니다.
> 사람·AI(문구/이미지 생성)·코드(`components/studio/CardFace.tsx`)가 **모두 이 문서를 기준**으로
> 같은 결과를 내도록 합니다. 레퍼런스(잘 만든 남의 카드뉴스)를 분석해 **"따라할 규칙"만** 뽑아
> 우리 프로젝트(`today-card`)에 맞춰 정리했습니다.
>
> **레퍼런스를 그대로 베끼지 않습니다.** 색·구도·타이포·분위기의 *원리*만 가져옵니다. (→ §7)
>
> **내용·흐름·장수(무엇을 어떤 순서·몇 장으로 말할지) 규칙은 짝꿍 문서 [`card-flow.md`](./card-flow.md)** 에 있습니다. 이 문서는 "어떻게 보이는가", card-flow는 "무엇을 어떤 흐름으로 말하는가"를 정합니다.

이 문서는 두 개의 짝으로 움직입니다.

| 파일 | 역할 | 누가 보나 |
|---|---|---|
| **`design-system/design.md`** (이 파일) | 글로 적은 **규칙 원본**. 모든 판단의 기준. | 사람 + AI 프롬프트 + 코드 리뷰 |
| **`design-system/card-news-design-system.html`** | 위 규칙을 **눈으로 보는** 디자인 시스템(색·글자 크기·예시 카드). 브라우저로 그냥 열면 됨. | 사람(빠른 확인) |

> 규칙을 바꾸려면 **이 문서를 먼저 고치고**, HTML과 코드를 거기에 맞춥니다. (이 문서가 "진실의 원본")

> **용어 (처음이라면):** **덱(deck)** = 한 번에 올리는 카드 묶음 · **풀블리드(full-bleed)** = 여백 없이 사진이 카드 끝까지 꽉 참 · **스크림(scrim)** = 글자가 잘 읽히게 사진 위에 까는 어두운 그라데이션 · **어절** = 띄어쓰기 단위 · **앵커(anchor)** = 글자 블록을 붙여 두는 기준 위치 · **NB2** = 제미나이 "나노바나나 2" 이미지 모델(→ §8)

## 0. 30초 요약 (TL;DR)

1. **세로 4:5 (1080×1350), 사진 풀블리드** + 어두운 그라데이션(스크림) 위에 글자.
2. 글자 블록은 **왼쪽 아래**(default `align '6'`)에 고정. 모든 장에서 위치·크기 **동일**.
3. 헤드라인은 **두꺼운 한글 산세(800↑), 아주 크게, 최대 2줄**, `word-break: keep-all`.
4. 색은 **고대비 흑/백** + 포인트색 1개만. 한 덱(deck)에 팔레트 1세트.
5. 이야기 흐름: **Hook → Pain → Steps → Result → CTA**. Steps는 **단계 수만큼 장을 늘린다.** *(가변 길이는 디자인 목표 — 현재 생성기는 5장 고정, → §5)*
6. 장식(말풍선·알림카드·`.zip`·세로 막대)은 **장당 1개까지**. 헤드라인을 이기면 안 됨.
7. 이미지 생성 API는 **Gemini 이미지 모델만** 사용 — 기본 NB1(저비용), 고품질은 NB2. (→ §8)
8. 레퍼런스 **복제 금지** — 로고·문구·사진·시그니처 장치를 그대로 쓰지 않는다. (→ §7)
9. **순서: 글(카드 구성표)이 먼저, 이미지는 그다음.** 구성표를 확정(`card-flow.md §4`)한 뒤에야 §8 이미지 생성을 호출한다.

## 1. 레퍼런스에서 뽑은 스타일 규칙

분석한 레퍼런스 5종(공통 DNA만 추출, 출처/브랜드는 베끼지 않음):

| # | 한 줄 요약 | 배경 | 분위기 | 가져온 규칙 |
|---|---|---|---|---|
| A | "꿀잠을 위한 파자마.zip" (밝은 침구 + 고양이 + 말풍선) | 밝음/에어리 | 포근·캐주얼 | 밝은 사진엔 **검은 글자**, `.zip` 제목, 장식 말풍선 1개 |
| B | "왜 몰랐지 진짜 느좋인데" (어두운 차 안 인물) | 어두움/무디 | 친밀·무드 | 어두운 사진엔 **흰 글자**, 반전 라벨칩(흰 박스/검은 글씨), 작은 서브카피 |
| C | "요즘 카드뉴스 트렌드.zip" (음료 + 떠 있는 책 카드) | 중립/베이지 | 에디토리얼·트렌디 | **둥근 카테고리 pill**, 큰 제목 2줄, 브랜드 로고 하단 |
| D | "재즈 거장들의 DM을 들여다보다" (흑백 인물) | 흑백/빈티지 | 음악·정통 | **흑백 그레이딩**, 인스타 알림카드(스토리텔링 장치), 페이지번호·핸들, CTA pill |
| E | "6월 남친 코디 — 화이트 팬츠 도전해볼래?" (횡단보도) | 저채도 거리 | 스트리트·패션 | **세로 막대 강조**, 핸들 표기, 질문형 후킹 제목 |

### 1.1 색감 (Color)
- **고대비 모노 텍스트**: 밝은 사진 → `#111110`(검정), 어두운 사진 → `#ffffff`(흰색). 그 외 색으로 본문 텍스트를 쓰지 않는다.
- **포인트색은 1개**만, 아주 절제해서(점 하나, pill 하나, 형광펜 1곳). 우리 토큰: `accentColor` (기본 팔레트 `#ffffff · #111110 · #9a8456 · #7c8f6b`).
- **한 덱(5장 이상) = 한 팔레트.** 배경색(`bgColor`)·포인트색(`accentColor`)은 덱 내내 고정.
- 사진은 **저채도·필름톤으로 그레이딩 통일**. 장마다 색온도가 튀면 안 됨.

### 1.2 구도 (Composition) — "왼쪽 아래 앵커"
- 글자 블록은 **왼쪽 아래**가 기본(레퍼런스 5종 중 4종). 우리 코드 `align` 기본값 `'6'`(=flex-end + left).
- **한 장 = 헤드라인 하나**. 나머지(라벨/서브카피/핸들)는 전부 보조.
- **세이프존**을 넉넉히. 인스타 그리드(3:4) 크롭에 글자가 잘리지 않도록 가장자리 패딩 유지. (4:5는 좌우 3.1%만 크롭 → 안전.)

### 1.3 타이포 (Typography)
- **헤드라인**: 두꺼운 한글 산세 `font-weight: 800`(강조어는 900), `letter-spacing: -.035em`, `line-height: 1.16`, **최대 2줄**.
- **서브카피/본문**: 보통 굵기, 훨씬 작게, `opacity ~0.85`, `line-height: 1.6`.
- **라벨/카테고리/메타**: 작게 + 자간 넓게 + 대문자(영문) 또는 짧은 한글. 두 형태 중 택1 — **외곽선 pill**(트렌드 표지) 또는 **반전 박스**(흰 배경/검은 글씨).
- 한글 줄바꿈은 **항상 `word-break: keep-all`**(어절 단위로만 줄바꿈, 단어 중간에서 안 끊김).

### 1.4 배경 (Background)
- **실사 사진 풀블리드.** 두 그레이드 중 하나로 통일: **Bright/Airy**(밝은 사진+검은 글자) 또는 **Dark/Moody**(어두운 사진+흰 글자). 대비가 보장되는 쪽을 고른다.
- **스크림(그라데이션) 필수.** 글자 닿는 가장자리를 어둡게. 우리 코드는 위·아래 그라데이션을 자동으로 깐다(`CardFace.tsx`의 `linear-gradient(...)`).
- 우리 정책상 **기사 사진은 자동으로 넣지 않는다**(저작권). 배경은 사용자 업로드 또는 NB2 생성 이미지(→§8).

### 1.5 분위기 (Mood) & 성격 장치
- 톤은 덱마다 하나로: 포근/무드/에디토리얼/빈티지/스트리트 등.
- **성격 장치는 장당 1개까지**(말풍선, 모의 알림카드, 이모지, `.zip` 파일명, 세로 막대 강조, 손글씨 워드마크). 재미를 주되 **헤드라인을 이기면 안 된다.**
- **후킹 제목 컨벤션**: ① 모음집 `~.zip`, ② 고백형 "왜 몰랐지", ③ 질문/도전형 "도전해볼래?". 호기심을 건드린다.

## 2. 한국어 제목·본문을 이미지 안에 직접 넣는 규칙

> 글자를 **이미지 위에 직접** 올리므로(별도 캡션 아님), 짧고·읽히고·안 잘려야 한다.

### 2.1 헤드라인(제목)
- **최대 2줄**, 한 줄 **6~12자** 권장(2줄이면 가장 임팩트 큼).
- 줄바꿈은 **의미 단위(어절)** 에서. 조사·어미를 줄 맨 앞에 외톨이로 두지 않는다.
  - ❌ `요즘 카드뉴스 트렌\n드.zip`  ✅ `요즘 카드뉴스\n트렌드.zip`
- **수동 줄바꿈을 쓴다.** 카드 텍스트의 `\n`은 그대로 반영됨(`white-space: pre-line`).
- **핵심어 1개만 강조.** `**굵게**`(weight 900) 또는 `==형광펜==`(포인트색 배경). 장당 강조는 1곳.
- 과장/허위 금지. 기사 제목·요약 범위를 벗어난 사실 추가 금지.

### 2.2 본문(서브카피)
- **한 줄 ≤ 약 20자, 1~3줄.** 한 문장으로 요지만. (본문 카드 `body`)
- `line-height: 1.6`, `opacity 0.85`, `word-break: keep-all` 동일.

### 2.3 라벨/카테고리/핸들
- 카테고리는 한 단어(예: `DAILY`, `마케팅 레퍼런스`). pill 또는 반전 박스.
- 핸들 `@handle`, 페이지번호 `0n / 05`(현재 코드는 5장 고정이라 `/ 05`로 출력 — 가변 덱은 `0n / 0T`, → §5)는 **메타 톤**(mono, 작게, opacity 0.6~0.7)으로.

### 2.4 안 잘리게 하는 안전장치(이미 코드에 있음)
- 글자가 카드보다 길면 **자동 축소**된다(`CardFace.tsx`의 AUTO-FIT: 자연 높이 > 가용 높이면 `transform: scale()`, 최소 0.4). **단, 이건 비상 안전망**이다 — 규칙(2.1)대로 짧게 쓰는 게 먼저.
- 폰트 크기를 키울 땐 **반드시 `font-size`로**(세로로만 커짐). `transform` 확대는 좌우로도 커져 크롭에 잘리므로 금지. (§3.1의 `sizeBump`도 `font-size`로 키워 세로로만 커지므로 **허용** — 두 규칙은 모순이 아니다.)

## 3. 모든 장에서 일관되게 보이는 규칙 (제목 크기·본문 크기·줄바꿈·위치)

> **목표: 독자가 "5장이 아니라 한 템플릿"으로 느끼게.** 한 번 정하고, 전 장에 똑같이 적용.

### 3.1 "한 번 정의, 전 장 적용" 토큰

> ⭐ 이 수치들의 **단일 원본은 `lib/designTokens.ts`** 입니다(`CardFace.tsx`가 import해 사용). 값을 바꾸려면 그 파일을 고치세요 — 미리보기·내보내기·스튜디오·/flow가 함께 바뀝니다. (클라이언트 렌더라 design.md를 런타임에 읽을 수 없어, 토큰만은 이 TS 파일이 원본이고 아래 표는 현재 값 스냅샷입니다.)

| 항목 | 값(미리보기 canvas 기준) | 비고 |
|---|---|---|
| 제목 기본 크기 `titleBase` | **42px**(canvas) / slide: 표지25·본문21·CTA23 / thumb 11 | 컨텍스트별 베이스 |
| 4:5 확대 `sizeBump` | **×1.4** (4:5 & thumb 아님) | 4:5에서만 키움(세로로) |
| 사용자 크기 슬라이더 `fontScale` | **0.7 ~ 1.5** (기본 1.0) | 장별 미세조정 |
| 최종 제목 크기 | `round(titleBase × fontScale × sizeBump)` | |
| 제목 굵기/자간/행간 | `800` / `-.035em` / `1.16` | 강조어 900 |
| 본문 크기 | `round(15 × sizeBump)`(canvas), 행간 `1.6`, opacity `0.85` | |
| 위치 `align` | 3×3 그리드 `'0'~'8'`, **기본 `'6'`(왼쪽 아래)** | |
| 폰트 `fontFamily` | 덱 전체 **하나**로 통일 | §3.3 |
| 패딩 | canvas 40 / slide 22 / thumb 12 | 세이프존 |
| 페이지번호 | `0n / 05` 형식, mono | 현재 5장 고정 표기 (가변 덱은 `0n / 0T`, → §5) |

### 3.2 일관성 4계명
1. **제목 크기 = 전 장 동일.** 한 장만 키우지 않는다(`fontScale`는 꼭 필요할 때만, 한 단계만).
2. **본문 크기 = 전 장 동일.**
3. **줄바꿈 정책 = 전 장 동일**(최대 2줄, keep-all, 어절 단위).
4. **앵커 위치 = 전 장 동일**(기본 `'6'`). 의도적으로 바꿀 때만 예외.

### 3.3 폰트 규칙
- **덱 하나 = 헤드라인 폰트 하나.** 선택지(`components/studio/data.ts`의 `FONTS`):
  - `''` 프리텐다드(기본·범용), `blackhan` 블랙한산스(임팩트), `dohyeon` 도현(굵은 고딕), `jua` 주아(둥근), `myeongjo` 나눔명조(명조), `pen` 나눔손글씨.
- 본문·라벨은 항상 프리텐다드/메타(mono)로 고정. 폰트를 장마다 바꾸지 않는다.

## 4. 카드뉴스 흐름: Hook → Pain → Steps → Result → CTA

> 5개는 "장 수"가 아니라 **역할(role)** 이다. 각 역할을 우리 카드 종류(`CardKind = 'cover' | 'body' | 'cta'`)에 매핑한다.

> 🔗 이 흐름으로 **자동 생성**할 때의 입력(주제·타깃·톤·최종행동)·장수 결정·**카드 구성표** 형식·프롬프트는 [`card-flow.md`](./card-flow.md) 참고. (이 문서=보이는 규칙, card-flow=내용 흐름 규칙)

| 역할 | 의미 | 카드 종류(`kind`) | 표면 | 핵심 |
|---|---|---|---|---|
| **Hook** | 멈추게 하는 한 방 | `cover` | 사진+스크림(다크) | 후킹 헤드라인 1개(§1.5 컨벤션). 표지엔 카테고리 pill·`밀어서 보기 →` |
| **Pain** | 독자의 문제/공감 | `body` | 사진/단색 | "이런 적 있죠?" — 문제를 한 문장으로 |
| **Steps** | 해결 방법(단계) | `body` × **N** | 사진/단색 | **단계마다 한 장**(→ §5) |
| **Result** | 그래서 얻는 변화 | `body` | 사진/단색 | 비포→애프터, 보상 |
| **CTA** | 팔로우·저장·공유 | `cta` | 단색(다크) | 멘트 + 핸들 + 해시태그 |

- **표면 규칙(코드 연동):** `cover`/`cta`는 다크 배경(`bgColor`) 위 흰 글자, `body`는 기본 흰 배경(검은 글자) — 단 `body`에 사진이 깔리면 스크림이 자동으로 켜진다(`dark || imageUrl`).
- **현재 생성기 상태:** `lib/ai.ts`는 기본 **5장(표지 + 본문×3 + CTA)** 을 만든다. 위 흐름은 그 5장을 **역할로 재해석**한 것이다:
  `표지=Hook`, `본문1=Pain`, `본문2=Step`, `본문3=Result`, `CTA=CTA`.
- **Steps가 많으면 5장으로 부족하다 → §5의 규칙으로 본문 장을 늘린다.** (단, **현재 생성기는 5장 고정**이다 — "본문 장 늘리기"는 §5의 *목표 규칙*. 구현 전까지는 본문 3장 안에서 한 장 1단계 원칙을 지킨다.)

---

## 5. Steps는 단계 수에 따라 여러 장으로 풀어야 한다

> 🚧 **현재 상태(꼭 읽기):** 지금 생성기(`lib/ai.ts`)는 **항상 5장 고정**(표지 + 본문×3 + CTA)으로 출력하고, 페이지번호도 `0n / 05`로 하드코딩돼 있습니다. 아래의 **"단계마다 한 장 / 총 N+4장" 규칙은 디자인 목표(아직 미구현)** 입니다. 가변 길이 덱을 쓰려면 §5.3의 확장이 필요합니다. **구현 전까지는** 본문 3장 안에서 Steps를 표현하되 *한 장 1단계* 원칙은 지키세요.

> **한 장에 여러 단계를 욱여넣지 않는다.** 단계 = 장(card). 3단계면 3장, 5단계면 5장. *(← 목표 동작)*

### 5.1 규칙
- **1단계 = 1장**(긴밀히 묶이는 두 동작은 한 장 허용, 그 이상은 금지).
- 각 Step 카드 구성: **단계 라벨**(`STEP 1`/`단계 1` 또는 페이지 라벨) + **단계 제목** + **한 줄 본문**.
- **번호를 항상 보이게.** 진행감(1/3, 2/3 …)을 준다.
- 제목 크기·위치·줄바꿈은 §3 그대로 — Step 장끼리도 완전히 동일하게.

### 5.2 덱 길이 공식
```
총 장수 = 1(Hook) + 1(Pain) + N(Steps) + 1(Result) + 1(CTA) = N + 4
예) 3단계 → 7장,  5단계 → 9장
```
- 페이지번호 표기 `0n / 0T`(T=총 장수)도 이 길이에 맞춘다(현재 코드의 `/ 05`는 5장 고정 표기 → 가변 길이를 쓸 땐 총 장수에 맞게 일반화 필요).

### 5.3 프로젝트 적용 메모(현재 vs 목표)
- **현재:** 생성기·페이지번호가 5장에 맞춰져 있다(`'0n / 05'`).
- **목표(이 규칙):** 본문(`body`) 카드를 **N개**까지 늘려 Steps를 표현. 스튜디오에서 본문 카드를 추가/복제하고, 생성기(`lib/ai.ts`)가 단계 수를 받아 본문 장 수를 가변으로 출력하도록 확장한다. (확장 전까지는 본문 3장 안에서 Step을 압축하되, **한 장 1단계** 원칙은 유지.)

## 6. (요약 표) 5역할 카드 스펙 치트시트

| 역할 | `kind` | 제목 예 | 본문 | 라벨/장치 | 위치 |
|---|---|---|---|---|---|
| Hook | cover | `왜 몰랐지\n진짜 느좋인데` | — | 카테고리 pill, `밀어서 보기 →` | `'6'` |
| Pain | body | `밤마다 뒤척인 적,\n있으시죠?` | 문제 한 문장 | `본문` 라벨 + `0n / 05` | `'6'` |
| Step n | body | `STEP 1\n온도를 1도 낮추기` | 한 줄 설명 | 단계 번호 | `'6'` |
| Result | body | `아침이\n가벼워졌어요` | 보상 한 문장 | `본문` 라벨 | `'6'` |
| CTA | cta | `팔로우하고\n더 보기` | 멘트 1줄 | 핸들 `@` + 해시태그 | `'6'` |

> ※ 페이지번호는 **현재 코드 기준 `0n / 05`(5장 고정)** 입니다. §4·§5의 7~9장 예시는 *목표 동작*(가변 `0n / 0T`)을 보여주는 것이니, 실제 출력과 헷갈리지 마세요.

## 7. ⚠️ 레퍼런스를 그대로 복제하지 말 것 (주의사항)

레퍼런스는 **규칙(원리)을 배우기 위한 자료**입니다. 결과물 자체를 베끼는 것이 아닙니다.

**가져와도 되는 것 (원리):** 4:5 풀블리드, 왼쪽 아래 앵커, 고대비 흑/백 + 포인트 1색, 두꺼운 산세 2줄, 스크림, 후킹 제목 컨벤션, "장당 장치 1개", 일관 그리드.

**절대 베끼면 안 되는 것 (그대로 복제):**
- 남의 **로고/워드마크/핸들**(예: `thep.`, `THICK.`, `@owncolor.kr`)을 그대로 넣기 — **상표·브랜드 침해.**
- 남의 **사진**(예: 그 고양이/인물/거리 사진)을 그대로 사용 — **저작권 침해.** (우리는 기사 사진 자동삽입도 금지.)
- 남의 **문구**를 토씨까지 복사.
- 시그니처 장치를 1:1로 모사(예: 그 브랜드만의 손글씨 워드마크 모양).

**왜?** 법적 리스크(저작권/상표) + 우리 브랜드가 "남 따라쟁이"로 보임. **우리 사진·우리 팔레트·우리 카피로** 같은 *원리*를 재현하세요.

## 8. 이미지 생성 API 조건 — Gemini 네이티브 이미지 모델만 사용 (기본 NB1, 고품질은 NB2)

> **규칙: 카드 배경/표지 이미지를 생성하는 모든 API 호출은 오직 Gemini 네이티브 이미지 모델만 쓴다.** 기본값은 저비용 **나노바나나(NB1)**, 더 높은 품질이 필요하면 **나노바나나 2/프로(NB2)** 로 올린다. 다른 이미지 생성기(Imagen, DALL·E, Midjourney, Stable Diffusion 등) 금지.

> 🔗 **순서 주의 — 글이 먼저, 이미지는 그다음.** 이 §8 이미지 생성은 **카드 구성표를 확정한 뒤**에만 호출한다(`card-flow.md §4`). 구성(제목·본문·장수)이 틀리면 이미지를 다시 뽑아야 하므로, 구성표 → (사람 확인) → 이미지 순서를 지킨다.

### 8.1 "나노바나나"가 뭔가요? (용어 정리)
- **나노바나나(NB1)** = 구글의 `gemini-2.5-flash-image` 별칭. ← **기본값(저비용, ~$0.039/장).**
- **나노바나나 2 / 나노바나나 프로(NB2)** = `gemini-3-pro-image-preview`. 고품질 옵션(~$0.134/장) — `IMAGE_MODEL`로 전환.

### 8.2 구현 위치 & 스위치 (단일 진실원)
- 파일: **`lib/image.ts`** — 상수 `MODEL`이 이미지 모델 ID. 환경변수 **`IMAGE_MODEL`** 로 덮어쓴다.
- 라우트: **`app/api/image/route.ts`** (관리자 전용, `ADMIN_COOKIE` 검증).
- 호출 방식(유지): `POST https://generativelanguage.googleapis.com/v1beta/models/{MODEL}:generateContent`,
  body `{ contents:[{ parts:[{ text: <프롬프트> }] }], generationConfig:{ responseModalities:['IMAGE'] } }`,
  헤더 `x-goog-api-key: <LLM_API_KEY>`. 응답에서 `inlineData.data`(base64) 추출.
- **`lib/image.ts`는 2단계다:** ① **컨셉(텍스트)** 호출 — OpenAI 호환 chat(`.../openai/chat/completions`, `Authorization: Bearer <LLM_API_KEY>`, 모델 `gemini-2.5-flash`)로 장면 아이디어를 만들고 → ② **이미지 모델** 호출(위 `x-goog-api-key` + native `generateContent`)로 그린다. 그래서 한 파일에서 **인증 방식(Bearer vs x-goog-api-key)·URL이 두 종류** 나타난다. (①이 실패하면 직접 프롬프트로 폴백 — 베스트에포트.) **§8 규칙(Gemini 이미지 모델 고정)은 ②이미지 호출에만 적용**된다.

```bash
# .env.local — 이미지 모델(미설정 시 코드 기본값 NB1 사용)
# IMAGE_MODEL=gemini-2.5-flash-image     # 기본(NB1, 저비용 ~$0.039/장) — 생략 가능
# IMAGE_MODEL=gemini-3-pro-image-preview # 고품질(NB2/Pro, ~$0.134/장)
LLM_API_KEY=AIza...   # https://aistudio.google.com/apikey
```

> **설정 확인:** 코드 기본값을 NB1(`gemini-2.5-flash-image`, 저비용)으로 맞춰 두었습니다. 더 높은 품질이 필요하면 `IMAGE_MODEL`로 NB2를 켜세요.
>
> ⚠️ **401/403/404가 나면** 키에 해당 모델 권한이 없는 것입니다. NB1은 대개 활성이고, NB2(`gemini-3-pro-image-preview`)는 프리뷰라 신규 키에서 비활성일 수 있어요 — 그땐 `IMAGE_MODEL`을 생략해 NB1으로 쓰면 됩니다.

### 8.3 프롬프트에 항상 박는 제약(브랜드 안전)
- 글자/숫자/로고/워터마크 **금지**, 실존 인물 **금지**, **하단을 어둡게**(흰 헤드라인 가독성). → 실제 문구는 **§8.5 `IMG-CONSTRAINTS` 블록이 단일 원본**(`lib/image.ts`가 런타임에 읽음).
- 2단계 생성(컨셉→이미지)으로 스톡사진 같은 진부함을 피함. 기본 룩은 풀컬러·현실적·고CTR(`trend`), 흑백 에디토리얼(`editorial`) 옵션. → 룩 문구도 §8.5 블록이 원본.

### 8.4 "이미지 생성"과 "텍스트 생성"은 다른 호출
- **이미지(이 §8 규칙 적용):** `lib/image.ts` → 위 모델.
- **텍스트/문구/해시태그/컨셉/계정분석:** `lib/ai.ts`, `lib/styleAnalyze.ts`, `imagineConcept` → **텍스트 모델 `gemini-2.5-flash`**(별개). 이 규칙(§8)은 **이미지 생성에만** 적용된다.

### 8.5 이미지 프롬프트 원본 (코드가 런타임에 읽음)

## 10. 카드 만들기 전 체크리스트

- [ ] 4:5(1080×1350)인가? 사진 풀블리드 + 스크림 있는가?
- [ ] 글자 블록이 **왼쪽 아래**, 전 장 위치 동일한가?
- [ ] 헤드라인 **2줄 이내**, keep-all, 어절 줄바꿈, 강조 1곳인가?
- [ ] 제목/본문 크기가 **전 장 동일**(`fontScale` 남발 안 함)한가?
- [ ] 폰트가 덱 전체 **하나**인가? 팔레트 1세트인가? 포인트색 1개인가?
- [ ] 흐름이 **Hook→Pain→Steps→Result→CTA**인가? Steps는 **단계마다 한 장**인가?
- [ ] 장식은 **장당 1개 이하**, 헤드라인을 안 이기는가?
- [ ] 이미지 생성은 **Gemini 이미지 모델**(기본 NB1 `gemini-2.5-flash-image`)인가?
- [ ] 레퍼런스의 로고·사진·문구를 **복제하지 않았는가?**
